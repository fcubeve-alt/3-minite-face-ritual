# 示范视频交付规格

> 给做视频的人（外包、素材站、或者以后的虚拟形象生成）。
>
> **把文件按下面的名字放进 `App/FaceRitual/Resources/CoachVideos/`，App 会自动用上，代码不用改一行。**
> 没放的动作会回落到示意动画 + 一行「Demo video coming soon」，流程不会断。
>
> 最近更新：2026-09-07

---

## 一、要交付什么

一个动作一段视频，共 20 段（GM-01 … GM-20）。

| 项 | 要求 | 为什么 |
| --- | --- | --- |
| 文件名 | `coach_gm_01.mp4` … `coach_gm_20.mp4` | App 按这个名字找文件，**错一个字符就找不到** |
| 格式 | H.264 MP4（`.mov` / `.m4v` 也认） | iOS 原生解码，不需要额外库 |
| 画幅 | **竖屏 9:16**，建议 1080×1920 | 上半屏是竖的，横屏会两边留大黑边 |
| 时长 | **4–8 秒，一个完整动作循环** | App 会自动循环播放，不需要凑够 15 秒 |
| 首尾 | 首帧与末帧姿势要接得上 | 循环播放时接缝才不跳 |
| 声音 | 不需要（App 播放时强制静音） | 语音提示由 App 自己念，两路声音会打架 |
| 体积 | 单段 ≤ 3MB，20 段合计 ≤ 60MB | App Store 有下载体积影响转化 |

### 文件名怎么来的

由动作编号自动生成：`GM-01` → `coach_gm_01`。规则在
`GoldMove.makeStep`（`mediaAsset` 字段），改名要连代码一起改，
所以**直接照抄上面那张表最省事**。

## 二、画面内容要求

### 必须

- **正对镜头的半身/头部特写**，手部动作要完整可见
- 动作**慢**。这是教学示范，不是展示。宁可比正常速度再慢一点
- 左右侧动作：视频里做**用户的左侧**即可，App 会在换边时提示，不需要两个版本
- 背景干净、光线均匀。用户在早上、卫生间、光线不一定好的环境里看这段

### 不要

- **不要出现任何功效表述**（字幕、口播、片尾都不行）。
  不能说"紧致""提升""减少细纹""瘦脸"，也不能暗示做了会变好看。
  这不只是合规问题 —— 代码里有检查规则盯着文案，视频同理。
- 不要加片头片尾、logo 动画、转场。用户每 15 秒就要看一段新的，片头是纯干扰
- 不要烧录字幕。文字提示由 App 显示，还要随语言变

## 三、放进项目

```
App/FaceRitual/Resources/CoachVideos/
├── coach_gm_01.mp4
├── coach_gm_02.mp4
└── …
```

`project.yml` 的 sources 是按目录抓的，**新文件不需要改配置**。
放完跑一遍：

```bash
python tools/check_coach_videos.py
```

它会告诉你哪些到位了、哪些还缺、哪些命名不对。

App 里 Settings → Developer → Diagnostics 也有一行素材进度。

## 四、虚拟形象（如果走这条路）

Owner 提到过用虚拟人物来做示范。工程侧的要求**完全一样** ——
上面那张表不区分素材是真人拍的还是生成的。

有两点值得先想清楚：

1. **手部动作是最难的部分。** 目前的生成模型在"手指按在脸颊特定位置并缓慢滑动"
   这类动作上很容易出畸形手。挑素材时优先看手，脸反而好办。
2. **一致性。** 20 段最好是同一个形象、同一套光线、同一个角度。
   逐段生成很容易漂成 20 个不同的人。

如果一时拿不到合格素材，**不影响上架前的其他工作** ——
回落的示意动画是可用的，只是不好看。素材什么时候到位，什么时候放进去。

---

## 五、这份规格为什么长这样

App 里视频只负责"怎么做"，**计时归播放器管**：

- 视频是 4–8 秒的循环，动作要做 15–20 秒 → App 循环播放
- 换动作、倒计时、换边提示、暂停，全由 routine 播放器控制
- 所以视频**不需要**和动作时长对齐，也不需要自带计时

这样拆开的好处：以后调动作时长（Expert Gate 很可能会调）不用重新剪视频。
