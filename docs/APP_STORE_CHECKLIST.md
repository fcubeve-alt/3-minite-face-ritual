> 给 Owner。第一次发 iOS App 会遇到的全部硬性要求，按「什么时候需要」排序。

> 这里只列会卡住提交的项。锦上添花的（本地化、iPad 适配、Widget）不在此列。

- [x] **用户协议（EULA）** —— 用 Apple 标准版，已接进代码，无需自己写
- [ ] **隐私政策网页** —— 草稿已写好（`site/privacy.html`），需要你发布并给我网址

## 需要 Apple 开发者账号

- [ ] **Apple Developer Program** 99 美元/年
      免费账号只能装到自己手机上、7 天过期；**上架必须付费账号**
- [ ] **App Store Connect 里建 App 记录**
- [ ] **配置订阅商品** —— 月费 $4.99、年费 $29.99（你已定）
      商品 ID 要和代码里一致：
      `com.faceritual.premium.monthly` / `com.faceritual.premium.yearly`

## 隐私标签（提交时苹果会逐项问你）

好消息：按现在的代码，全部可以选 **"Data Not Collected"（不收集数据）**。

| 苹果会问 | 你的答案 | 依据 |
| --- | --- | --- |
| 收集联系信息吗 | 否 | 没有账号系统 |
| 收集健康数据吗 | 否 | 练习记录只存本地，不上传 |
| 收集照片/视频吗 | 否 | 摄像头帧只在内存过一遍就丢 |
| 收集位置吗 | 否 | 没用定位 |
| 用于追踪吗 | 否 | 没有广告标识符、没有第三方 SDK |

⚠️ **如果以后接入第三方 analytics**（规格 §19 待决），这张表、隐私政策、
App 内的摄像头说明**必须一起改** —— 隐私标签填错是常见的下架原因。

## 提交材料

- [ ] **截图** —— 至少 6.7 吋（iPhone 15/16 Pro Max 尺寸）一组
      ⚠️ 必须用**正式内容**截，现在满屏 MOCK 角标，不能拿去提交
- [ ] **App 描述 / 关键词 / 推广文本**
      ⚠️ 措辞要守规格 §4/§13：不得出现抗衰、除皱、穴位疗效、「年轻 X 岁」这类表述。
      健康美容类的功效宣称是苹果审核的重点
- [ ] **分级问卷** —— 大概率是 4+
- [ ] **审核备注** —— 建议主动写清：
      「AR Mirror 需要前置摄像头才能演示核心功能，请在真机上测试。
        摄像头画面全程在设备端处理，不上传。」
      审核员用模拟器测不到 AR，写清楚能少一轮打回

## 顺序建议

1. **现在**：发布隐私政策与支持页 → 把网址给我 → 我填进代码
2. **接着**：定产品名 → 做图标 → 买域名（可选）
3. **然后**：真机跑 AR POC → 决定 AR 是否继续（规格 §18）
4. **之后**：你和专业人员替换正式动作内容（见 `docs/CONTENT_AUTHORING.md`）
5. **最后**：付费开发者账号 → 截图 → 提交

第 1 步不依赖任何其他事，现在就能推进。
第 4 步是最耗时的，但**必须等第 3 步结论出来**再投入 —— 否则可能白做。
